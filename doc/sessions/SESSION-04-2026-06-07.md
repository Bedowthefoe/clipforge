## What was done

### Subtitle timing standards (Option D + E)

1. Researched Netflix / BBC / TikTok subtitle timing standards.
   - Netflix: min 5/6 s (0.83s), max 7s (long-form) / 2.5s (short-form), 17-20 CPS Latin
   - 2-frame inter-event gap minimum (0.08s @ 25fps)
   - Short-form (TikTok/Reels): show subs slightly before speech; predictable rhythm > exact word-sync
2. Analysed v13 actual timing: durations from **0.12s to 4.44s** — horrible distribution. Root cause: trusting Whisper word END times (silence-biased).
3. Implemented **Option D — reading-rate uniform pacing**:
   - Each event duration = `clamp(chars / target_cps, min_dur, max_dur)`
   - Discarded Whisper word end times entirely
   - Cumulative starts from segment start
4. First attempt with `target_cps: 30` (Latin equivalent) — every event hit the 0.83s floor (text packed too tight). Switched to `target_cps: 18` (matches Thai speech rate). Result: 42 events, all 0.83-1.28s, span exactly matches video duration.
5. **Discovered cleanup bug:** v14 still had bad timing (single-syllable events with 2-3s gaps after). Root cause: cleanup applied `out_segments[idx]["text"] = corrected` which **overwrote 67-char segments with the 19-char correction substring**. Fixed with surgical substring replace. Documented in [debt 001](../debt/001-cleanup-bug-fixed.md).
6. v15 with cleanup fix: clean Netflix-compliant timing throughout. 42 events, 0.83-1.28s, no big gaps.

### Per-line speech anchoring (Option E)

7. Operator noted timing still drifts from speech within segments (Option D anchors only at segment boundaries). Proposed Option E: per-line Whisper-word START anchoring.
8. Implemented in `split_into_timed_lines` — for each line, look up Whisper word containing first character, use its `start` as anchor.
9. Honor host pauses up to `max_drift_correction: 1.0s`; otherwise stay cumulative.
10. v17 results: 42 events, durations 0.83-1.28s (still Netflix-compliant), 1 detected real pause (0.34s before "เห็นใครมีปัญหา..."), several micro-anchors visible as 0.12-0.17s gap variations.

### Font + Thai mark stacking

11. Diagnosed Prompt font's tone-mark/vowel collision: only **5 GPOS lookups** total — insufficient for Thai mark-to-mark anchoring.
12. Researched alternatives: Sarabun has 8 GPOS lookups (good but looped), IBM Plex Sans Thai has **15 GPOS lookups** (excellent + loopless).
13. Installed `fonts-ibm-plex` via apt.
14. Switched config to `font: "IBM Plex Sans Thai"`. v16 high-res crop showed marks now stacking cleanly above vowels.
